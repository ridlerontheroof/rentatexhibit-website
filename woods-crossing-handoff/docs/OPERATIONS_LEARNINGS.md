# Operations & Platform Learnings — Woods Crossing

Hard-won lessons from running Exhibit On Superior in production on Replit that aren't
covered by the SEO/AEO, AppFolio, or UTM/Analytics playbooks. Apply these when building
and operating the Woods Crossing site.

## 1. Replit production serving

- **Serve production through your own Express server, not the static edge.** The static
  platform layer can't do compression, cache-control, security headers, non-slash 301s,
  or real 404s. Run a small Express server (autoscale) that parses the same rewrite table
  the platform uses so routes stay in one authoritative place.
- Precompress at build time (`.br`/`.gz` siblings written as the LAST build step); the
  server does no runtime compression. Health probe endpoint (`/healthz`) for autoscale.
- Ship CSP as Report-Only first; flip to enforced via an env flag only after verifying
  GTM/YouTube/Maps/AppFolio embeds in production.
- **Trust proxy:** behind Replit's edge, set Express `trust proxy` to private/loopback
  CIDR ranges, NEVER a numeric hop count. With `trust proxy: 1` every visitor resolved to
  `127.0.0.1`, collapsing all per-IP rate limits into one shared bucket. The edge strips
  client-supplied X-Forwarded-For, but there are multiple internal hops.

## 2. Deploy runtime observability

- Deployment logs drop roughly the **first ~25 seconds of stdout** after an instance
  starts — "server listening" and watchdog startup heartbeats are never visible. Don't
  design liveness signals that only fire at startup; verify a new watchdog via a
  build-stamp check + manual probe + the next daily heartbeat instead.
- The deploy runtime has **no headless Chromium** — any production self-check that would
  use a browser needs an HTTP-only fallback.
- No deploy webhook exists: to react to a publish going live, stamp a build-id into the
  build and run a workspace watcher that polls the live site for a new stamp, then runs
  post-publish checks (and IndexNow submissions for new/changed URLs — Bing/Copilot honor
  IndexNow; Google ignores it).

## 3. Domain & redirect traps

- Registrar-level apex→www forwarding (Squarespace and similar) **strips query strings**
  (kills ad attribution) and its rules may silently fail to save while Domain Connect
  presets still hold the apex records — delete the presets first, then verify with curl.
- The platform's directory-index 301 beats non-slash rewrites: when a zero-redirect URL
  matters (ads), use the trailing-slash form.
- Legacy-URL 301s: serve real single-hop 301s from the production server (a meta-refresh
  stub is a fallback, not the mechanism). Keep the old-site URL inventory as the parity
  checklist (see URL_PARITY_MAP.md).

## 4. Alerting & email operations

- **Route technical/watchdog alerts to an owner alert address; the leasing inbox receives
  only real lead traffic.** Mixing them buries leads (owner-mandated on Exhibit).
- Throttle each alert reason to once a day; "N failures in M minutes" alarms must count an
  exact trailing window with one persisted row per event (expiry = event + window) — time
  buckets double-count at window edges.
- Claim-before-send patterns (weekly digests etc.) must release the claim in EVERY send
  failure path, including the escalation alert's own catch, or one failure silences the
  whole period.
- Gmail SMTP with an app password (see the AppFolio playbook §8). nodemailer `raw`
  messages need an explicit envelope `{from, to}` or sends fail. Branded emails embedding
  a logo must attach it as an inline CID part (multipart/related) or Gmail shows a broken
  image box.
- SPF/DKIM/DMARC live wherever the sender domain's nameservers point — for
  highlandptrs.com that's AppFolio's DNS zone (ns*.apmdns.com), not the registrar.

## 5. Images & share cards

- Per-image byte budget (~195KB) must be met with encoder size-targeting
  (`webp:target-size`) at FULL pixel width — never by shrinking the largest srcset rung,
  or full-width images render blurry on dense displays (keep the largest rung ≥ ~1920px).
- Generate OG share cards (1200×630) with a script from a page→photo/tagline map, and add
  a byte-compare freshness test so stale cards fail the build. Never hand-run ImageMagick.
- iMessage/Apple link previews are generated by the sender's device at send time and are
  NOT re-fetched on message edit — a broken card on an old/edited bubble proves nothing.
  Verify the raw prerendered OG head server-side, then resend as a NEW message. Apple's
  scraper executes no JS; the raw prerendered head is what it consumes.

## 6. Build & test discipline

- Bake external-data snapshots (availability) into the build, but refresh the snapshot's
  timestamp even when data is unchanged — a staleness guard plus a quiet week otherwise
  fails the publish build.
- Dist-dependent tests must gate on the build's LAST output file (e.g. the final
  precompressed artifact), or they run against a half-built dist and fail spuriously.
- Guard tests that scan source files for factual claims (sqft, prices, phone) must decode
  unicode escapes first and exclude phone numbers/CSS shade numbers from numeric regexes.
- Fail-loud beats silent fallback everywhere: every external-feed parser should count
  raw vs accepted rows and alarm when everything gets dropped (see the AppFolio slot-format
  incident — the site showed "no tour times" for weeks while openings existed).
