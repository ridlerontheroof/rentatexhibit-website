Parameter and Filter URL Controls

Search engines are discovering parameter URLs such as:

```text
/available-units?plan=5-2br-1-std
```

The filtered URL returns substantially the same page as the base availability page.

Required fix

• Use /available-units as the canonical URL.
• Exclude parameter URLs from XML sitemaps.
• Do not create permanent internal links to temporary filter states unless needed.
• If query parameters are retained for usability, canonicalize nonunique filtered pages to /available-units.
• Do not block these URLs in robots.txt before crawlers can process their canonical.
• Create clean standalone floor-plan URLs only for durable, unique plan pages.

Acceptance test

• Filter URLs have the correct canonical.
• Search Console does not report large volumes of duplicate parameter URLs.
• The sitemap contains no ?plan= URLs.
• Internal navigation favors clean URLs.

Full Cache Disinfection Runbook

Phase 1 — Hosting and CDN purge

Replit or the hosting provider must perform the following:

1. Purge all cached HTML responses.
2. Purge edge-cache entries for every legacy URL.
3. Purge cached redirects.
4. Purge current inventory HTML and API responses.
5. Purge old service-worker caches.
6. Bump any service-worker cache version.
7. Remove or unregister any legacy service worker that still references G5 or RentCafe assets.
8. Confirm the new redirect table is deployed at the edge before application routing.
9. Republish the site.
10. Run a second full purge after the redirect deployment.

Recommended cache policy

Dynamic HTML and inventory pages:

```text
Cache-Control: no-cache, max-age=0, must-revalidate
```

A short controlled CDN TTL may be used if availability updates still propagate promptly.

Inventory API responses:

Use no-store or a very short cache period where technically appropriate.

Fingerprint-versioned assets:

```text
Cache-Control: public, max-age=31536000, immutable
```

Do not use year-long caching for unversioned HTML, JSON, or inventory responses.

Search-Engine History Removal Runbook

Principle

Old URLs must first return the correct permanent redirect, 404, or 410 response. Search-removal tools do not replace correct server behavior.

Do not block old URLs in robots.txt before Google and Bing can crawl the redirect, 404, or 410.

────────

Step 1 — Deploy the complete redirect map

Highest-priority redirects

```text
/availableunits.aspx → /available-units
/amenities.aspx → /amenities
/brochure.aspx → /floor-plans
/mapsanddirections.aspx → /map-directions
/video.aspx → /virtual-tour
/apartmentphotos.aspx → /photo-gallery
/contactus.aspx → /contact-us
/floorplans.aspx → /available-units
```

Old G5 family

```text
/apartments/il/chicago/floor-plans → /available-units
/apartments/il/chicago/amenities → /amenities
/apartments/il/chicago/photo-gallery → /photo-gallery
/apartments/il/chicago/virtual-tour → /virtual-tour

/apartments/il/chicago/map-directions → /map-directions

```

Apply the same redirect to trailing-slash variants.

Step 3 — Google Search Console cleanup

After redirects are live:

1. Submit the clean XML sitemap.
2. Inspect each destination URL.
3. Select Test Live URL.
4. Request indexing for the destination.
5. For urgent stale results, open the Removals report.
6. Submit temporary removal or Clear snippet requests for the exact stale URLs.
7. Use prefix removal for /apartments/il/chicago/ only after every URL in that family has a correct permanent destination.
8. Monitor the Page Indexing report for:
  • Redirected
  • Duplicate
  • Soft 404
  • Crawled, not indexed
  • Alternate page with canonical
9. Confirm that the indexed version matches the live version.

Priority Google requests

```text
/availableunits.aspx
/amenities.aspx
/brochure.aspx
/contactus.aspx
/floorplans.aspx
/mapsanddirections.aspx
/video.aspx
/apartmentphotos.aspx
/apartments/il/chicago/
```

Google’s Removals tool is temporary. Permanent cleanup still depends on redirects, 404/410 responses, noindex where appropriate, and removal from the sitemap and internal links.

────────

Step 4 — Bing and Copilot cleanup

1. Verify the site in Bing Webmaster Tools.
2. Submit the corrected sitemap.
3. Use Bing’s Content Removal or Block URLs tools for urgent stale results.
4. Submit all changed, redirected, and deleted URLs through IndexNow.
5. Submit the destination URLs as changed.
6. Monitor Bing’s indexing and AI Performance reports.

IndexNow supports submission of redirected, updated, 404, and 410 URLs.

────────

Step 5 — Refresh stale public snippets

If a search result continues to show old data after the live page has changed:

• Use Search Console’s snippet-clearing workflow as the verified owner.
• Use Google’s public Refresh Outdated Content tool when ownership access is unavailable.
• Submit the exact URL shown in the search result, including relevant parameters or casing.
• Repeat for each separate indexed URL variation.
